# 市场分析逐页 Visual

## 适用边界

服务于已明确论点的客户提案页面。先读适用 AGENTS.md、该 P 的正文与最新确认记录、可复算 Excel／直接来源和已有图。尊重用户指定的文件、平台、品牌色和当次例外；以下视觉风格是市场分析工作区偏好，不用于覆盖其他任务的品牌设计要求。

本 Skill 管选图、视觉表达、制图闭环；来源和推导不足时调用 review-market-analysis，不用画面补造证据。进入研究补充要同步归档、来源审计和底稿更新。

只 Review 的请求仅检查已有图、数据和展示，不重新生成、改图、升版或发布；下面的制作闭环只在用户要求制作／修改时执行。

## 1. 制图前先写简短 Visual Contract

首次采用指标、代理量、评分或比较维度时，先复用 review-market-analysis 的 [研究口径与指标可用性表](../review-market-analysis/references/research-usability.md) 判定其用途；同一口径已有有效审计时直接引用。依据不足先调整论点或表达形式，再写 Contract。

保存在工作底稿，不能作为客户图内文案：

- P／Visual ID，单一主要论点及需要被看见的关系；
- Graph 或 Non-graph、选用形式、主视觉与辅助视觉分工；
- 每个数字的原始来源 ID、Excel Sheet／Range／公式，或直接引用的原文位置；
- 已启用 [证据关系图谱](../review-market-analysis/references/evidence-graph.md) 时，复用图中数据／判断对应的 Evidence、Scope、Claim ID；制图后补齐该图的 Use 和 Location；
- 指标、国家／品类／人群、年份、单位、分母及 Actual／Estimate／Forecast／Scenario；
- 指标可用性判断及证据位置；沿用时注明对应版本；
- 时间覆盖与缺口、比较基准、标题和必要限定；
- 强调对象、颜色／背景阶段、是否需要唯一红框、标注方案；
- 交付介质、尺寸、可编辑源、导出路径及实际 QA 容器。

先选数据关系和图形，再选工具。主视觉通常一个；只有辅助图确实补上重要论点时才增加 1–2 个，不能机械凑三个模块。

## 2. Graph 与 Non-graph 路由

| 需要表达的关系 | 优先形式及注意事项 |
|---|---|
| 可比指标的逐期变化 | 折线、柱或面积；用足够真实点呈现形状，稀疏年份不能补成连续 Actual |
| 两个离散时点／情景端点 | 成组柱、斜率图或端点对比；不拟合虚构的连续增长趋势 |
| 份额／构成 | 100% 堆叠或少量构成对比；分母一致、类别穷尽且互斥才可合计 |
| 单一数值或短途适配等重要事实 | 指标卡，归 Non-graph；无需为一张卡强造统计图 |
| 品牌、城市、产品、人群多字段比较 | 可读的表／矩阵；统一维度、单位和证据层级 |
| 两项指标的联合分布 | 散点／四象限；每个点的两轴均有适用且可比的依据，评分按可用性表说明方法；缺值不填造坐标 |
| 机制、流程、产品价值链 | Infographic／流程图；箭头明确是因果证据、推断还是顺序 |
| 转化阶段 | 有同一批次人数才画定量漏斗；渠道分工无流转数据时画流程，不制造流失率 |
| 品牌定位 | 有依据的维度矩阵或定性对比；无量化依据不能伪造精确坐标、气泡大小或评分 |

### 量化工具选择

- 数值计算优先在 Excel 固化，按任务使用当前可用的 Data Analytics、Spreadsheets 技能。
- 最终是 Excel 原生可编辑图时，优先原生图表；最终是静态 PNG／SVG 时，可用 Matplotlib／Seaborn 等可复现工具读取已审计输出，或合适的 Excel 导出。
- 明确标注“原生可编辑图表”与“嵌入图片＋可复算数据”的差别，不能把图片工作簿说成图形原生可编辑。
- 不为截一个图随意切换用户要求的交付介质；涉及 HTML、幻灯片等使用该介质的适用技能。
- 模型生图不承担坐标、比例、数据标签或精确定位的真实呈现。

### Infographic 可选工具：AntV infographic-creator

- 机制、流程、时间线、层级、双方对比等信息结构适合模板表达时，可选用 `$infographic-creator`；它是制作工具之一，不是每页或每张 Non-graph Visual 的必经步骤。现有形状、排版或其他工具更适合时继续沿用。
- 选用前先确认当前环境已安装 infographic-creator，并读取其 SKILL.md；未安装时使用其他适合的制图工具。传入本页已审计的文案、数字、关系类型、尺寸与样式；不为适配模板补造数值、比例或因果箭头。
- 本工作区的 Visual Contract、证据口径、客户文案、白底／青色重点／其余置灰和逐 P QA 继续适用；模板的多色、渐变、3D 或示例配色不覆盖项目要求。AntV 通过语法和代码渲染，按确定性工具处理；只有实际调用 Image2／imagegen 时才进入下节的生图流程。
- 按约定保留 Infographic 语法、HTML 制作源及实际导出件；最终交付仍服从用户指定介质，需要静态图时导出 SVG 或合适格式后放入最终容器，不因工具默认 HTML 改成交付网页。生成语法成功不等于图已渲染或导出；检查实际尺寸下的文字、箭头、图标、来源和裁切。

### Non-graph 与 Image2

比较表、矩阵、流程、指标卡可用可编辑形状／排版或适合介质的确定性工具；设计叙事图确有需要时使用可用的 Image2／imagegen。

生图输入仅提供本次已批准的论点／文案／数字、必须用的参考图、尺寸、风格及交付目标。描述本次要得到的完整画面，不拼接历次回改历史。修改图按图像工具要求先查看并传入正确参考图，验收数字、文字、单位、图形与来源。

是否派遣代理遵守当前用户授权和适用项目规则。图像工具不可用时选用适合任务的可复现图形方案，并如实说明实际制作方式。调用 imagegen 等技能时遵守其工具和参考图规则。

## 3. 工作区视觉风格

- **白底、无网格线。** 保留理解数值必要的轴、刻度或基准线；不用装饰网格增加噪声。
- **重点颜色聚焦，其余置灰。** 默认青色为主强调、深色正文、灰色背景数据；品牌色有明确要求时随之调整。不用多个饱和色争夺注意力。
- **一个组合页最多一个红框 highlight，允许零个。** 只圈重要差异或关键机制，辅以一句短标注；不把整个模块或所有数据都框起来。
- **Trendline 按数据需要使用。** 实际系列连接线、统计拟合线、预测线含义不同；标明方法和属性。不把虚线作为每图装饰，不凭两点画趋势拟合。
- **同页避免重复套路。** 不让主图与 supporting 图都采用“柱状＋虚线＋红框”；形式变化必须仍适合各自的数据关系。
- **时间在横轴。** 阶段性／逐年变化可用浅色背景分区突出节点；阶段起止有来源或明确为分析定义，不能凭颜色虚构加速期。
- Actual 与 Estimate／Forecast／Scenario 使用文字加线型、点型或分隔明确区分；颜色分区不能替代属性标注。非连续口径分面或断开，不能由连续线掩盖。
- 图题表达已获证据支持的关键判断；副标题／标签交代指标、范围、时段及单位。来源短注保留原始机构与年份，完整 APA 和计算路径在页面 Sources／底稿。
- Visual Contract 可以记录指标不兼容等审查结论；客户图题则呈现有用事实本身，例如分别标明“年度销量基线”和“长期存量情景”，不把“口径不同、必须分别解读”当成市场洞察。若现有数据无法支撑本页主论点，标记需补证据或改论点，而非用技术备注充当主视觉。
- 关键数字和标签直接可读，层级清楚；不靠缩小字体塞内容。整体与单图在实际客户展示尺寸下检查。
- 不用 3D、装饰渐变、无依据气泡面积或双轴制造差异。量值柱通常从零开始；窄轴或差值图必须显式标注尺度并有合理理由。
- 图内只保留市场判断、事实与必要限定，去掉研究流程、自审说明和内部转场。

## 4. 数据语义预检

绘图之前检查；发现冲突先换表达或补证据：

- 同图比较是否同一指标、单位、地理、品类、人群和分母？**年度销量与累计存量即使都叫“辆”，也不能构成同一趋势序列。**
- 历史、当前和预测是否覆盖标题宣称的期间？旧系列之后有新证据但口径不同，可加独立模块说明新阶段，不能默默接线。
- 原始值、公式输出和图中舍入数字一致吗？增幅是百分比还是百分点？CAGR 年数、币种和价格基期是否一致？
- 来源只有顾虑清单、没有各项占比时，用文字／定性卡并注明“机构未披露占比结构”，不做伪百分比表。
- 类别是否互斥？性价比、社区、智能等品牌杠杆可叠加，不画成份额饼。
- 样本城市的 proxy 分类是否被画成全区域销量排名？客户域名访问是否被画成市场份额或转化漏斗？
- 短时间／小样本只呈现能够证明的端点、量级或分布，不增加假时间点让图显得完整。

## 5. 逐 P 制作闭环

`制作 → 主代理自审 → 用户 Review → 修改或 Pass → 下一 P`

1. 保留已确认稿和既有组件；修改另存明确版本，不静默覆盖批准图。
2. 导出实际交付件，检查单图及组合页；打开交付工作簿核实最终图表／图片位置，不只检查临时 work 文件。
   已启用图谱时，Location 绑定本轮导出件及最终容器的路径、哈希和图号／Sheet位置；更新采用关系。修改图题、数据或结论后，沿 Use 找到相关正文与摘要，重新审查受影响输入。
3. 主代理自审四项：
   - 数值与语义：原文／Excel／图表一致，指标和分母可比；
   - 论证：图能直接支撑本页主要判断，辅助图各有作用；
   - 版式：文字清晰、不碰撞／裁切、强调克制、阶段背景及标签正确；
   - 交付：源文件、导出、最终容器、正文引用与版本对应。
4. 交给用户本轮实际预览、交付文件与简短自审结果；未执行的检查明确列出。
5. 用户打回后重开该 P 状态，修正文案／图／底稿的受影响内容并复审；用户确认后才进下一 P，除非用户明确安排批量处理。
6. Visual 确认不自动授权外部同步，也不确认图内新增的研究结论。需要发布时走项目发布审计。

保留可复算数据、绘图源／原生形状、导出图、Visual Contract 与自审记录；可沿用现有 VisualPack／校验记录，不额外建立重复的一套目录。
