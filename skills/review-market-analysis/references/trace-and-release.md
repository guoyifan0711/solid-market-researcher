# 三流追溯与交付记录

这是内部审计记录格式，不复制进客户 Big conclusion 或 Visual。沿用项目已有等价 Sheet／表格，优先补缺字段，不为符合模板重建所有文件。

## 1. Claim 追溯

稿件审计涉及量化、画像、比较或关键定性判断时使用。按 [证据关系图谱](evidence-graph.md) 将核心结论、引用证据、口径及实际采用位置连成网络；该附件维护节点、关系、TTL表达及查询方法，本文件维护计算与交付证据。

`Source → Evidence＋Scope → Use＋Location → Claim → 下游 Claim`

派生数在对应 Claim 中保留 `Excel 输入／公式／输出`。直接引用和定性判断沿实际证据路径登记。

| 字段 | 记录内容 |
|---|---|
| Claim ID 与位置 | 唯一 ID、P／Part、句子或图表 ID；区分事实、计算、分析推断、建议 |
| 证据与使用关系 | Evidence ID、Scope ID、Use ID、Location ID；同一数据可有多个采用位置，支持／反证／背景分别登记 |
| 原始来源 | Source ID、机构、标题、URL、本地原文、页／表／段及数据期 |
| 输入 | 工作簿、Sheet、Range；输入原值、单位、总体及 Actual／Estimate 等属性 |
| 计算 | 公式与位置、分母、期间、权重及假设；直接引用填“直接引用” |
| 输出 | 输出单元格、未舍入值、展示值与舍入规则 |
| 应用 | 正文和 Visual 用了哪一输出；APA 条目对应哪些原始来源 |
| 推导 | 原数据支持哪一判断、机制、重要替代解释及边界 |
| 结果 | 已验证／差异／未验证；检查日期、方式及证据 |

不以填表本身替代读取原文或复算。定性 Claim 无须造数值公式，但须有来源及推导；单个直接引用可在来源摘录中定位，不要求额外建一本 Excel。

### 重要区分

- **原始来源 APA：**机构／作者、已披露的日期、标题、URL；页码或表号补充定位。缺日期使用合适的无日期写法，不能拿访问日期伪造发布日期。
- **Calculation Trail：**基于哪些 Source ID，在哪个工作簿、Sheet／Range、公式和假设计算。
- **Cross-validation：**独立来源验证哪一项规模、方向、机制或商业价值；不得把计算路径当第二个来源。

### 三流反向检查

1. 报告中的关键数字是否找到输出或原文？
2. 输出是否使用正确输入、公式、年数及分母？
3. 输入是否与正确原文版本、币种、市场和数据期一致？
4. APA 是否指向该原始来源，而不是仅写计算工作簿？
5. 图中的值、标签、时间和 Forecast 属性是否与正文同步？
6. 画像中每个字段是否来自适用样本？多个字段组合时是否仍只是分析合成？
7. 图谱是否存在循环支持、只有背景却没有支持路径、引用地点换版或口径改变后仍沿用旧审查？
8. 来源或关键数字发生变化时，所有关联正文、图、摘要和下游结论是否已逐处处理？

## 2. 当前交付清单与回归检查

整合／确认／发布审计使用。在 README 或既有状态文件维护当前入口，历史版本保留原状态。

| P／Part | 正文路径／版本 | Excel／输出位置 | Visual 路径／版本 | 审计记录／结果 | 用户确认依据 | 外部目标／版本／回读 |
|---|---|---|---|---|---|---|

不要凭最大版本号、日期或“确定版”文件名推断用户已确认。允许既有工作簿名称含“待确认”，但清单必须指向用户实际审阅的精确文件或哈希，不把任意中间件当交付件。

每次更改按 [跨页依赖表](argument-dependencies.md) 的改动类型确定复核范围，并将受影响位置及结果登记到本轮记录。该附件统一维护影响检查方法与定义的使用关系，此处维护版本、三流与发布证据。

### 发布前后验收

发布前固定批准基准（路径／版本／必要时哈希）、目标 URL／ID、要写入的范围和授权依据；比较内容而不只比较页数。

写入后记录目标 ID、外部 revision（可得时）、实际回读时间、身份及核对结果。关键标题和大结论按批准表达检查；数字、单位、图表及术语不能仅靠标题存在来推断完整。

如果平台格式不同，允许等价排版转换；不能在转换中改写判断、丢表格／图片或把普通文本识别成公式。发现差异后保留证据，按原授权范围修正或报告差异。

## 3. 审查记录最小格式

- 对象、精确版本、P／Part、当前模式及范围；
- 结论：Ready to share／Share with caveats／Needs revision；
- 问题：证据位置、会改变什么判断、严重性与修正要求；
- 检查：实际复算项、来源追溯、渲染／回读方式和结果；
- 未验证／不适用项及原因；
- 用户确认与外部发布状态分别记录。

局部变更记录可短，但不能写“全部通过”掩盖未检查部分。新来源必须重新进入来源审计；老审查报告不能自动覆盖后来新增的预测、画像字段或图表。
