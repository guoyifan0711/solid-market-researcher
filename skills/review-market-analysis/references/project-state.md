# 新项目状态模板与维护

只在新建项目或用户明确要求迁移状态时使用。模板不包含案例结论，不会自动回填已有客户项目。

## 启动

1. Coordinator 读取已有输入，按 [研究启动项与必要追问](research-usability.md#1-研究启动项与必要追问) 明确决策目的、对象、市场、时段和交付要求。目标／范围模糊或信息不足以确定研究路线时，必须分轮向用户提问；相关回答明确前，可整理材料及推进独立工作。已知信息与用户授权的取舍直接沿用。
2. 使用 [README 模板](../assets/project-readme.md) 建立项目入口，使用 [骨架模板](../assets/narrative-skeleton.md) 记录启动约定和本次页面任务卡。启动约定引用已有依据，剩余缺口留在当前交付清单；不复制其他项目的 SKU、页数或状态。替换模板变量，表格按实际分析框架填写；不原样交付未填模板。
3. 使用 [空白机器清单](../assets/project-state.json) 建立 `项目/05_校验记录/当前交付清单.json`。v1 固定使用该目录层级，`project_root` 为 `..`；所有产物路径相对项目根目录，不填个人绝对路径。其他旧布局不自动迁移。
4. 执行 `render_state.py` 生成同目录 `当前交付清单.md`。README 和骨架只链接该入口，不再各写一份“已确认／待研究”表。启动阶段没有正文时，`baseline.path=null`；此时检查不通过是正常状态，不能填虚假文件绕过。

新项目保留模板中的 `trace_graph` 扩展，首次初始化由 agent 生成固定 `project_id`。研究取得引用内容时按 [证据关系图谱](evidence-graph.md) 填写 Evidence／Scope，成稿时补 Use／Location／Claim；图谱快照作为当轮审查产物登记。旧项目按本轮授权与影响范围补齐，不自动回填所有历史稿。

机器清单字段与命令见 [可执行检查](executable-checks.md)。只更新 JSON 源清单，再重生成可读视图；不反向修改生成 MD 来掩盖缺口。

## 状态职责

| 位置 | 维护什么 | 不维护什么 |
|---|---|---|
| AGENTS.md | 长期规范与项目例外 | 研究进度、实时市场结论、客户批准版本 |
| README | 项目入口与材料位置 | 与清单重复的状态表 |
| 叙事骨架 | 启动约定、各页问题、边界、必要证据及后续输入 | 与清单重复的版本／确认状态 |
| 当前交付清单 JSON | 对象、当前产物、哈希、Claim 映射、审计、确认、外部版本与缺口 | 无依据的通过状态 |
| 历史审计／确认记录 | 当时检查范围、证据、用户决定和精确版本 | 自动替新版本背书 |

## 每次状态变更

- **Research 新增来源：**登记 Source ID、原文／摘录、原始 APA、审计和访问状态，再连接 Evidence／Scope 与受影响 Claim。新引用、口径或采用位置变化时同步 Use／Location，重新审查相关输入；由当前清单生成新图谱快照。
- **首稿／修订：**登记具体正文及页标题、Excel／Visual 和哈希；本页状态为待确认。新版本不能直接继承旧版本的通过标记。
- **用户确认：**记录用户原话或消息定位、所指版本与范围。文字、数据底稿、Visual 分开记录；没有独立制图确认时，不代填确认。
- **打回／改页／换数据：**受影响的正文、图及依赖重新进入待确认；移页同步 Page ID、骨架和引用。未变页可继承已核实的页面内容哈希及依据，不要求全项目从头重审。
- **准备发布：**以用户批准表达固定基准，登记本次目标、范围与候选文件。清单中的授权标记只是记录，不代替真实授权。
- **发布后：**保存实际回读、平台 revision／时间／身份；对照批准基准查文字、数字、表格、图像及渲染。外部出现未解释修改时记录差异，不能自动覆盖另一端。
- **收尾：**清单同时保留已完成和未闭合项；项目结束不等于所有证据缺口清零。

工作簿文件名含“待确认”但已被用户认可时，登记精确文件／哈希与确认依据即可，不机械重命名；最大版本号也不能替代确认记录。

## 回退和沿用

更新清单前保存有意义的历史版本或差异记录。仅讨论全局规范时，不触碰具体客户 README、骨架或成品。已存在等价状态系统的项目沿用其入口，不为了格式一致建立第二套状态。
