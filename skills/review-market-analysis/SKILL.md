# 市场分析自查与验收

## 目标与边界

同时判断“证据／计算是否可靠”和“它是否足以支持客户将读到的结论”。公式无报错、来源权威、图片生成成功，都不能单独构成通过依据。

先读适用 AGENTS.md、页面任务卡和当前版本／确认记录。遵守用户指定的审查范围；只 Review 时不改文件或外部页面。审查不等于允许发布，不把自审通过写成用户确认。

新项目启动或维护交付状态时读取 [状态模板与维护规则](references/project-state.md)。已有项目只在用户要求的范围内迁入，不自动改写历史客户项目。

采用下列模式之一或必要组合。只对真实执行的检查标记通过，不要求局部文案改动重跑全部历史研究。检查无关、非关键部分可标 N/A；无法读取核心材料应标未验证及影响。

## A. 来源及研究覆盖审计

新项目或目标／范围有实质变化时，先读 [研究启动项、追问与指标可用性](references/research-usability.md) 的启动部分。恢复已有输入；缺少会改变研究路线的用户决定时，按问题依赖分轮提问并等待回答，再进入相关研究。信息已充分的项目直接继续。

首次测算或选用新指标时，按同一附件确定证据能支持的范围；一轮 Research 完成或新增来源时，更新相应取舍并执行以下审计。复用既有任务卡与来源登记。

1. **先审问题覆盖。** 对页面任务卡列出必要证据项，逐项判定“充分／部分／缺失／不适用”。当前规模、历史趋势、最新时段、未来方向与驱动机制依题意选择，不能用容易获取的邻接数据替代真正问题。
2. **再审每个来源。** 读取已获得的正文，核对原文位置、本地存档、机构／日期、数据截止期、国家／品类／人群、单位、样本／方法、Actual／Estimate／Forecast／Scenario。原文、摘录、索引必须对应同一来源版本。
3. **审时效。** 旧研究可证明历史基线；是否需要新证据取决于结论使用时点。公开日期新不代表数据新。机构 Forecast 可用作预测，不升级成当前 Actual。
4. **审独立性及适配。** 记录 Main Source 与 cross-validation 各自验证规模、方向、机制还是商业价值。共享底层模型或互相转引不算独立验证；跨国、共享系统、上游技术需限制用途。
5. **审缺口和反证。** 保留不利或冲突证据。核心来源受阻时记录精确路径、已读／未读、所需内容、替代尝试、受影响 Claim、blocking/high/medium/low 及原因。按 [P0 来源获取决策](references/research-usability.md#p0-来源获取决策) 将所有报告获取缺口汇入本 Part 清单，P0 排前；由 Coordinator 随本 Part 或多 Part 阶段结果统一交用户审核是否协助获取／购买，不逐报告提问或中断流程。缺口影响的判断待核或收窄，其他研究继续。

输出覆盖与可用性判断、来源审计结果、关键冲突及缺口决策，可合并在既有记录中。取得可引用内容后，按 [返回原文的实质审查](references/source-grounded-review.md) 先独立重建来源口径，再按 [证据关系图谱](references/evidence-graph.md) 登记Evidence、Scope及采用位置。每项口径保留原文锚点、原词和解释；不得从旧Scope复制答案后标verified。缺证据时收窄测算、比较或排序，并检查依赖结论。

## B. 稿件与分析审计

在提交或重交P／Part前执行。涉及数字、图表、画像、比较或关键定性判断时，读取 [三流追溯](references/trace-and-release.md)、[证据图谱](references/evidence-graph.md) 和 [原文实质审查](references/source-grounded-review.md) 的相应部分。必须返回原文核对定义、研究总体、数据期、分母和方法，再逐字段比较当前报告原句；区分支持、反证和背景。verified、签名或“见原文”均不能代替这层判断。

骨架形成后记录关键上游判断的后续用途；改稿时按 [跨页依赖表](references/argument-dependencies.md) 选择复核范围，同时核对重复使用的定义与分级。小修改直接在本轮审计中列出受影响位置即可。

已有机器清单时，再按 [可执行检查](references/executable-checks.md) 导出图谱并运行本轮页面的 inventory／trace。完整稿提交或全量回测须在coverage_documents登记实际核对稿件，对账原稿链接与Reference；其他格式补等价核对。trace／release同时检查图谱结构、版本和审查输入绑定。只检查登记网络不能宣布全量覆盖；直接引用和定性判断不强制造Excel公式。

### 1. 页面逻辑

- 标题和大结论回答本页问题；宏观页不提前固化 SKU、客群或渠道策略。
- Supporting 的多个小结论能共同支撑 Big conclusion；主结论不比支持证据更强。
- 关键判断出现在结论中，不只藏在 supporting；正文按“小结论。原始机构指出具体事实”组织。
- 政策、技术、需求或基础设施不仅被列举，还说明它改变了哪一项采用条件。把既有需求、近年约束变化、未来驱动区分开。
- 核心洞察、关键数字与必要限定直观可读；内部研究安排、回改说明不出现在客户正文或图中。

结论成立后，再按写作 Skill 的 [提案正反例库](../write-market-analysis-pitch/references/pitch-before-after.md) 检查中文表达并复读修改后的完整句段；论证问题和用语问题分别处理。

### 2. 计算与三流一致性

- 追踪所有主结论的数字与关键 supporting 的 Claim ID；逐个确认原文、Excel 输入／公式／输出、报告句子／图表、APA 原始来源连接成立。
- 独立复算会改变结论的比例、CAGR、增幅、份额、价格换算、加权汇总、分母和情景；直接引用核对原文，不造无意义公式。
- 查公式缓存／重算结果、外链、合计、舍入、单位、零分母、时间跨度。代码成功与公式错误数为零只证明技术检查的一部分。
- GMV、厂商收入、销量、出货、存量、共享 trips、网站访问分别保留定义。跨源、跨总体或跨指标比较不以“量级接近”放行。
- Reference 写原始作者／机构与可用日期、标题、URL；Calculation Trail 写底稿定位并回链原始来源。Excel 自身不是商业结论的外部证据。

### 3. 商业推导

按实际出现的结论检查：

| 结论类型 | 必须检验的关系 |
|---|---|
| 市场增长／份额扩大 | 同一市场边界的历史与当前／预测；共享宏观背景是否真的解释相对增长 |
| 未来五年判断 | 长期需求、约束变化与持续条件；机构验证的是何地、何类产品及何种预测，不伪造统一模型 |
| 城市／地区优先级 | 先明确级别衡量的维度，再分别核对适配、增长及竞争依据；投入金额所需条件另列，样本阈值与权重有出处或分析定义 |
| Persona | 每个特征对应来源及总体；车主不等于全部买家，边际比例不等于联合画像；未知职业保持未知 |
| 媒体／达人效果 | 触达、偏好、自报影响与因果转化区分；受众分母明确，覆盖率不能当 ROI |
| 产品／定位 | 已核实 SKU 能力匹配已证明的需求；“适合”与“相对竞品独特”分别论证 |
| DTC 表现 | 行为指标可说明现状差距，不能独立推断信任、记忆、销量或转化原因 |
| 营销任务 | 从市场、画像、SKU、客户及竞对现状收束优先事项；不凭空承诺预算或收入 |

建议与分析推断可以存在，但在内部记录其依据、机制、替代解释和验证方向；客户语言的确定程度与证据相称。不能因为分析判断进入 Excel 就标为统计事实。

### 4. 视觉与展示

对本次涉及的图至少检查数值、指标／分母、年份、实际／预测属性、标题和结论一致性。非简单视觉调用工作区的 build-market-analysis-visuals，并按其标准审视真实输出；该 Skill 负责具体画法，此处判断是否支持业务结论。

导出的图、表、工作簿在最终容器里实际打开或渲染。图片数量、文件存在、临时文件正常或导出日志成功，不能代替成品检查。若只能部分检查，要记录覆盖范围。

## C. 整合、确认与发布审计

执行此模式时读取 [三流追溯与交付记录](references/trace-and-release.md) 的“交付清单与回归检查”，按跨页依赖表核对本轮采用位置，覆盖正文、图表、摘要及Notes／术语附录。

对采用机器清单的新项目执行 [可执行检查](references/executable-checks.md) 的 compare／release；发布范围的确认、证据覆盖及语义审计必须有与当前内容绑定的记录。外部授权和实际回读另行核验。历史项目没有机器清单时沿用等价人工检查，不能为套用新流程而擅改客户文件。

- 检查全篇页序、边界、术语、图表、摘要和分部结论一致；摘要不产生新的数字或判断。
- 本地与外部发生差异时，以用户批准内容及确认记录为判断基准，不能自动用最新日期覆盖另一端。
- 发布前完成批准稿与待发布内容的差异核对；只有已获相应授权才调用外部写入工具。
- 写入后使用同一明确身份回读实际目标，核对标题、大结论、关键数字、表格、图片、APA 与术语，检查换行和“无效公式”等渲染问题。
- 未执行外部写入或未能回读时，发布检查为 N/A／未验证；不能因本地审查通过就报告外部同步完成。
- 更新当前交付清单，不覆盖历史记录；“已确认”仅对应明确版本，不能替未解决数据背书。

## 审查结果与停止条件

使用三个状态，不另造不透明评分：

- **Ready to share：**本轮范围内的关键证据、推导和交付检查通过；只剩不影响判断的润色项。
- **Share with caveats：**核心方向可用，非阻断局限已清楚保留；列明它们如何限制使用。核心计算未验证不能借此放行。
- **Needs revision：**核心来源／分母／计算／比较错误，主结论超出证据，重要检查未执行，或批准与交付内容不一致。修正、补查或收窄后再交付。

每轮记录：版本与范围、实际检查及证据位置、问题与影响、需要的修正、仍未验证项、结果和确认／发布状态。既有校验记录可追加新一轮；只读任务在回复中给出结果。

自查通过不替代用户 Review。收到“打回”后，重新检查被修改内容及依赖；不要只改一句正文，却留下旧图、旧 Summary 或旧发布稿。
